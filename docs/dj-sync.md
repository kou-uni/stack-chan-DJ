# DDJ-FLX2 連携 — DJに合わせて踊らせる

**結論：できる。ただし踊りを自宅の頭脳に置くと、絶対に間に合わない。**
会話とダンスは別系統に分ける。

---

## 1. まず遅延の話（ここが設計を決める）

BPM 128 の1拍 = **469ms**。
会場 → Funnel → 自宅 → 推論 → 戻り の往復は、条件が良くても数百ms。

**往復が1拍を丸ごと食う。拍を1つずつ送る方式は成立しない。**

### だから、拍を送らない

送るのは **テンポと位相だけ**。刻むのは実機側。

```
Mac（DJ卓の隣）──「BPM=128.0, 次の1拍目は t=…」──▶ スタックチャン
                    数秒に1回でいい                    実機が自分で刻む
```

`00-concept.md` の3層モデルでいう **①反射層**。ネットワークが揺れても踊りは崩れない。
逆に言えば、**ダンスのロジックはファーム側に置く数少ない例外**になる。

---

## 2. 拍をどこから取るか

### A. Ableton Link ← 本命

rekordbox は Ableton Link に対応（**Performance モードのみ**。Export モードでは動かない）。
LINK を ON にすると、BPM と拍位置がネットワーク越しに配れる。

- 一番きれい。DJ側の操作を邪魔しない
- サードパーティの `rkbx_link` が Link / OSC でタイミングを出す実装として存在する
- 注意：コントローラ接続中は TEMPO スライダーでLinkのBPMを変えられない（Link 側の画面で操作）

### B. MIDI を直接読む ← 演出トリガーはこれ

**DDJ-FLX2 はクラスコンプライアント**（ドライバ不要）。macOS に USB MIDI デバイスとして出る。
`mido` / `rtmidi` で数十行。まずここから始めるのが早い。

### C. 音からビート検出

ループバック音声でオンセット検出。環境に強いが、遅延と誤検出が乗る。**保険扱い**。

### 採用：A で拍、B で演出

拍の正確さは Link に任せ、「いつ何をするか」は MIDI から取る。

---

## 3. マッピング（叩き台）

| DJ側の操作 | スタックチャン |
|---|---|
| Link の拍 | 首を横に振る（**2拍に1回**が基本） |
| PLAY 押下 | 踊り出す。目を開ける |
| CUE / 頭出し | 首をピタッと止める（キメる） |
| パフォーマンスパッド | 表情を切り替える（笑う・驚く） |
| ジョグを回す | **首も一緒に回る** ← 一番ウケる。触らせられる |
| フェーダー / フィルター | 首の振り幅を変える |
| Smart Fader / Smart CFX | 12個のLEDの色を変える |

**ジョグに首を追従させるのは最優先で作る。** 参加者が自分の手で回して、
その場で首が動く。説明が1秒も要らない。

---

## 4. サーボを壊さないための制約

- 縦 90° / 横 360° 連続回転、フィードバック付き2基
- BPM128 を全拍で振ると **往復 4.3回/秒**。発熱と摩耗に直結する
- → **2拍に1回を基本**にして、サビだけ全拍に上げる
- → 曲間は必ず休ませる。動かし続けない
- 振り幅は小さめから。大きく振ると台から落ちる
- **電源が入った状態で首を手で回さない**（ハードが壊れる）。DJに触らせる前に一言必要

      スタックチャン ──Funnel──▶ 自宅 Mac Studio          ＝ 会話（遅延は許容）

**未解決：この2系統に同時接続できるか。**

現実解は **モード切替**。同時接続は狙わない。

- **DJモード**：会場のMacに繋いで踊る。会話しない
- **会話モード**：自宅に繋いで喋る。踊らない

進行としてもこの方が良い。踊っている最中に会話させると、どちらも中途半端に見える。

## 6. 作る順番

1. `mido` で DDJ-FLX2 の MIDI を**ただ表示する**だけのスクリプト（30分で終わる。ここで機種の癖が全部わかる）
2. ジョグ → `move_head` を繋ぐ（**最初に効く成果**）
3. PLAY / パッド → 表情・LED
4. Ableton Link から BPM を取る
5. テンポと位相を実機に渡し、**実機側で刻ませる**（低遅延化）

1 と 2 は**スタックチャン本体がなくてもMac側だけで書ける**。
遠隔ワークベンチが立つ前でも先に進められる。→ [remote-workbench.md](remote-workbench.md)

コードは `../app/dj/` に置く。

## 7. 物理構成（段階別）

制御は **Wi-Fi 経由**。USB は給電と書き込みにしか使わない。
つまり机の上では、スタックチャンは電源ケーブル1本だけで自由に置ける。

### Step 1：今日できる（スタックチャン不要）

```
DDJ-FLX2 ──USB-C──▶ Mac
```

これだけ。バスパワーなので電源アダプタも要らない。
`midi_dump.py` を走らせて、つまみを捻ったら何番のCCが出るか見る。

### Step 2：首を振らせる（宅内）

```
DDJ-FLX2 ──USB-C──▶ Mac Studio ──2.4GHz Wi-Fi──▶ スタックチャン
                                                    ▲
                                          USB-C（足側）= 給電のみ
```

- スタックチャンは**同じLANにいればいい**。Mac とはWi-Fi越し
- Mac 側で gateway（WebSocket 8765）を上げて、そこに繋がせる
- USB は給電だけ。**足側に挿す**（頭側だと首が回って自分で抜く）
- 台に固定する。サーボが動くので、放っておくと机の端まで寄っていく

### Step 3：イベント当日

Mac Studio は持ち出せないので、DJ側の制御は MacBook が担当する。

```
iPhone ──USB──▶ MacBook ──内蔵Wi-Fiで2.4GHz APを立てる──▶ スタックチャン
                    ▲                                        ▲
              DDJ-FLX2（USB-C）                     モバイルバッテリー
```

**ポイント：MacBook 自身を親APにする。**

iPhoneのテザリングに MacBook とスタックチャンの両方をぶら下げる形だと、
**クライアント同士が通信できるか（AP isolation）が読めない**。ここで詰むと現場で直せない。

代わりに、
1. iPhone を **USB で MacBook に繋いでテザリング**（回線はここから）
2. MacBook の**内蔵Wi-Fiを「インターネット共有」で 2.4GHz AP に回す**
3. スタックチャンをその AP に繋ぐ

こうすると MacBook が直接ゲートウェイになる。経路が1つ減って、確実性が上がる。

### 電源

| | 電源 |
|---|---|
| DDJ-FLX2 | USBバスパワー（MacBookから） |
| スタックチャン | **モバイルバッテリー必須**。内蔵550mAhは持たない |
| MacBook | 電源が取れる席を確保する。APとテザリングでバッテリーを食う |

### 会場での注意

- **DJ卓の上は振動する。** スタックチャンは卓の上に置かない。別の台に固定する
- 落下は現場では直せない。周囲を空ける
- 電源が入った状態で首を手で回さない。**DJに触らせる前に一言言う**

## 8. 「リズムを刻む」と「ニコニコする」の作り分け

両方できる。ただし難易度が全然違う。

### ニコニコする ← 簡単。数行で終わる

`set_avatar` / `set_mouth` / `set_blink` は stackchan-mcp に**既にあるツール**。
MIDIのボタンを1つ拾って呼ぶだけ。表情は Neutral / Happy / Sleepy / Doubt / Sad / Angry。

| きっかけ | 表情 |
|---|---|
| PLAY を押す | 笑う |
| フィルター全開 / パッド連打（盛り上がり） | もっと笑う |
| CUE で止める | 真顔でキメる |
| 曲間・無音 | 眠そうにする |

**曲間に眠そうにするのは入れた方がいい。** ずっと笑っていると置物に見える。
落差があると「反応している」ことが伝わる。

### リズムを刻む ← 段階がある

| 段階 | 拍の取り方 | 手間 | ズレ方 |
|---|---|---|---|
| **v0** | PLAY押下を1拍目とみなし、**BPMは手入力**で周期を回す | 30分 | 曲を変えるとズレる。DJがテンポを触るとズレる |
| **v1** | **Ableton Link** から BPM と拍位置 | 半日 | ズレない。テンポ変更にも追従 |
| 保険 | 音からビート検出 | 中 | 会場では誤検出しやすい |

**v0 でも「曲に合ってる」ようには見える。** 1曲は3〜5分なので、曲ごとに PLAY で打ち直せば実用になる。
イベントに間に合わせるなら v0 を先に完成させて、v1 は余裕があれば。

### 刻ませるときの実装メモ

- **2拍に1回にする。** BPM128の全拍は往復4.3回/秒でサーボが保たない。
  人間も2拍・4拍で頭を振るので、2拍に1回の方がむしろ自然に見える
- **先読みオフセットを入れる。** サーボは瞬間移動しないので、拍のジャストに
  「振り終わっている」ようにするには数十ms早く動かし始める必要がある。実測で詰めるパラメータ
- **曲間は止める。** 動かし続けると発熱するし、無音で首を振っていると壊れて見える

# 9. 実装アーキテクチャ（2026-09-08・gateway の実物を読んで確定）

**自作する量が激減した。** gateway 側に受け口が3つあり、要件がきれいに割り当たる。

| 要件 | 使う仕組み | 性質 |
|---|---|---|
| 音楽が流れると踊る・光る | **`beat_mode_start()`** | gateway 内で完結。配線不要 |
| **つまみ → 首を回す（yaw）** | **`stackchan_follow_pose_stream(url)`** | 連続。外部WSを購読 |
| **つまみ → うなずく（pitch）** | **同上**（同じフレームの `pitch`） | 連続 |
| **ボタン → 表情を変える** | **MCP ツール呼び出し**（`set_avatar` / `set_mouth`） | 離散 |
| パッド → LED | `stackchan_follow_led_stream(url)` | 連続 |

## 連続と離散で経路を分ける

```
DDJ-FLX2 ──USB──▶ 自作の MIDI アプリ
                     ├─ つまみ ──▶ WSサーバ {yaw, pitch} ──▶ gateway が購読
                     │                (follow_pose_stream)
                     └─ ボタン ──▶ MCPツール呼び出し（set_avatar など）
```

**つまみは「状態」なのでストリーム、ボタンは「出来事」なのでツール呼び出し。**
この分け方は gateway の設計にそのまま乗っている。

## ★ 自分で書かなくてよくなったもの

`stackchan_follow_pose_stream` が既に内蔵している。

- **角速度クランプ**（サーボが唸らない）
- **ダウンサンプル**（間引き）
- 軸反転、pitch センター offset
- exponential backoff 付き reconnect
- **初期姿勢をデバイスから seed** するので、初回フレームから実サーボ位置基準でクランプが効く

以前このドキュメントに「間引き 30〜50ms とデッドバンドを必ず入れる」と書いたが、
**その層は既にある。** 自作するのは「MIDI を yaw/pitch に変換する」ところだけ。

可動範囲は **yaw ±90°、pitch 5〜85°**（SCS0009 の動作範囲）。

## 作る順番（改訂）

1. `midi_dump.py` で CC 番号を特定する ← **ここは変わらない**
2. **つまみ2つを yaw / pitch に変換して WS で吐くだけのサーバ**を書く
3. `stackchan_follow_pose_stream(action="start", url=...)` で購読させる
4. ボタン → `set_avatar` を MCP ツール経由で叩く
5. `beat_mode_start()` を重ねる（音で踊る層）

**2 が実質の作業量のすべて。** 数十行で済む。

# 10. 実装完了（2026-09-08）

`app/dj/console.py` に集約。gateway は**デーモンモード**で動かす。

```bash
cd vendor/stackchan-mcp/gateway
uv run stackchan-mcp serve --transport streamable-http   # → http://127.0.0.1:8767/mcp

./.venv/bin/python app/dj/console.py            # 実機に繋ぐ
./.venv/bin/python app/dj/console.py --dry-run  # 実機なしで確認
```

```
DDJ-FLX2 ──USB──▶ console.py ──┬─ pose  ws:8770 ─┐
                                ├─ LED   ws:8771 ─┤ gateway が購読
                                └─ 表情/脱力/口 ──┴─ MCP over HTTP :8767
```

**デーモンモードにした理由**：stdio は単一クライアント専用なので、
自作アプリを繋ぐと Claude Code から実機を触れなくなる。HTTP なら共存できる。

## 実装した5つ

| # | 機能 | 中身 |
|---|---|---|
| 1 | **脱力** | `sad` と連動してトルクを切る。二重切りなし、他の表情で自動復帰、8秒アイドルで自動脱力 |
| 2 | **まばたき** | 起動時にON。待機は首を動かさず、まばたきだけで生きている感を出す |
| 3 | **口をリズムに** | `beat_meta_snapshot` の BPM から `set_mouth_sequence` を積む。デバイス側キュー再生 |
| 4 | **LED** | 拍で明滅する専用ストリーム。`target="base"` で本体12個、外付けテープにも切替可 |
| 5 | **アバター差し替え** | `app/avatar/pack_avatar.py`。14枚のPNG → 537,600バイトの raw RGB565 |

## dry-run で見つけて直したバグ2つ

1. **脱力からの復帰が「つまみを回したとき」にしか書かれていなかった。**
   つまみを触らずに次の表情へ行くと脱力したまま。→ sad 以外の表情で必ず復帰させる
2. **つまみの値が一切ログに出ず、動作確認できなかった。**
   → 現在値をバー付きで表示。結果、両端まで走破しているのが見えて、
   同定した CC番号と入力範囲の正しさまで同時に裏取りできた
