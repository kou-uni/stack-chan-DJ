# 俯瞰図サイト「地図」— 設計

**2026-09-21 起案。UXはこの後。ここは骨格だけ。**

## 何を解こうとしているか

いまの B ブロックは、①構成 ②ファーム ③作り方 ④DJ が**それぞれ別の図**になっている。
**繋がりが絵になっていない。** 聞いている側は毎回「いまどこの話か」を頭で組み直している。

> **1枚の大きな地図を置き、そこをズームして回る。**
> ②③④ は新しい図ではなく、**同じ地図の一部を拡大したもの**になる。

**進行役は説明しない。地図が動いて、指すだけ。**

---

## 1. 原則（UXを決める前に、ここを固定する）

| | 原則 | なぜ |
|---|---|---|
| **P1** | **地図は1枚しかない。**新しい図を足さない | 「戻る場所」が1つだと、迷子にならない |
| **P2** | **移動は必ず連続。**瞬間移動しない | ズームの途中が見えることが、**部分と全体の関係の説明そのもの** |
| **P3** | **現在地が常に出ている。**全体の中のどこか | ズームすると人は必ず迷う。★事故の9割はここ |
| **P4** | **進行役の操作は「次へ」だけ** | 本番でマウスを探さない。矢印キー／クリッカー |
| **P5** | **どのシーンからでも入れる。**URLで直接 | 事故ったとき、その場面から再開できる |
| **P6** | **止まっても意味が読める。**アニメは補助 | 動きが止まった瞬間に無意味になる図は、資料として弱い |

## 2. 階層 — 3段で止める

**4段にしない。** 深いほど作れるが、当日「いまどこ」が言えなくなる。

```
  L0  全景         机の上の全部。実機・Mac・DJ盤・iPad・背景・LED
       │
  L1  系統（6つ）   ①構成 ②ファーム ③作り方 ④DJ ⑤声 ⑥演出
       │            ★B の①②③④ は、この4つへのズームとして実現する
       │
  L2  部品          MCPの49個／宣言的な状態／CC番号の対応／LED30粒の共有
```

**L2 は全部を作らない。** 当日話すものだけ。**地図に空白があるのは正しい。**

## 3. 画面の構造

```
┌─────────────────────────────────────────────┐
│                                    ┌───────┐│
│                                    │ ミニ  ││ ← P3 現在地
│          ビューポート               │ マップ ││   全景のどこを見ているか
│      （ここがズーム・パンする）      └───────┘│
│                                             │
│                                             │
│  ┌────────────────────────┐                │
│  │ いまの見出し（1行）      │                │ ← 何の話か
│  └────────────────────────┘                │
└─────────────────────────────────────────────┘
       ● ● ● ○ ○ ○ ○ ○ ○        ← シーンの進み具合
```

- **ミニマップは常設。**消さない
- **見出しは1行だけ。**説明文を置かない（喋るのは人）
- 下のドットは**全何場面の何番目か**。★聞いている側の「あとどれくらい」が解決する

## 4. 技術の選び方

| 選択 | 理由 |
|---|---|
| **SVG 1枚 ＋ `viewBox` を動かす** | 拡大しても文字が綺麗。`transform: scale` だと線幅と文字が潰れる |
| **カメラはデータで持つ** | シーン＝`{id, name, x, y, w, h, 強調する要素}` の配列。**絵とカメラを分ける** |
| **補間は ease-in-out、600〜900ms** | 速いと関係が読めない。遅いと待たされる |
| **`prefers-reduced-motion` を見る** | 酔う人がいる。その場合は即時切り替え |
| **要素の強調は CSS クラス1つ** | `.dim`（他を暗く）と `.hot`（対象を光らせる）だけ。増やさない |
| **背景スクリーンと同じ 8779 で配る** | `/p/map`。iPad からも同じURL |

### ★描画予算を守る

背景（`stage.html`）で一度やらかしている。**iPadが止まる。**
地図は常時アニメではないので余裕はあるが、**同じ検査を最初から入れる**。

## 7. 決めたこと（2026-09-21 試作）

**絵柄は「机の見取り図を土台に、論理を線で重ねる」。**

見取り図と系統図で迷ったが、**この会の結びが「出会う場所は、この机の上でした」**である以上、
**物理配置そのものが主張**になる。論理は、寄った先で線と札として描く。

実装で分かったこと（試作で直した）:

- **図の上に文字を寝かせない。**見出しは札にして下に置く。透かすと読めない
- **カメラは画面の縦横比に合わせる。**合わせないと寄ったとき片側だけ余白が出る
- **箱の説明は箱の中に入れる。**はみ出すと、浮いて見える

→ `docs/pages/map.html`（`/p/map`）。12場面。`←→` で移動、`0` で全景
