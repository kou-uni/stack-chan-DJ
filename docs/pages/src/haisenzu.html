DJ台の上のロボットは、
この部屋の中だけで動いている。

人がDJ機材をいじる。ロボットが踊る。背中のスクリーンが同じ色で光る。 話しかけると答える ── 考えているのも、この机の上のMacの中。 声も映像も、この部屋から一歩も出ません。

更新 2026-09-14 頭脳 Ollama / gemma3:4b 声 VOICEVOX 話者14

いまは Mac Studio 1台に全部載っています。 DJ機材もここに挿さっているので、この形のまま作り込めます。

読みどころ

01 / INPUT

DJコントローラーが、唯一の「人が触る入力」

つまみを回せば首が動く。パッドを押せばLEDの模様が変わる。 右のレコードを擦れば下からスポットライトが上がる。 音量ゲージを70%まで上げると、会場が赤く染まって花火が出る。

MIDI CC を角度・色・光量に読み替えているだけで、 特別な操作画面は一切ありません。 DJが普段やる手つきが、そのまま演出になります。

02 / SCREEN

iPadは「HTMLを開いているだけ」

背景のステージ映像は動画ではありません。 MacがWebサーバを立て、iPadはそのURLをブラウザで開いているだけ。 毎秒20回、いまの状態がWebSocketで届いて、その場で描かれます。

だから専用アプリも配線も要りません。 画面が増えたらURLを開くだけで増やせます。

03 / SYNC

実機のLEDと、背景のLEDは同じ配列

ロボットの足元に巻いた30粒のテープに送る色を、 そっくり同じまま背景スクリーンにも送っています。 画面側でそれらしく作り直してはいません。

背景の柱を這うテープ、スピーカーの溝、ウーファーの縁のリング。 全部この配列を映しているので、目の前の光と画面の光が必ず一致します。

04 / BRAIN

考えるところだけが、自宅のMacにいる

聞き取りも、考えるのも、声を作るのもぜんぶ自分のMacの中。 外部のAPIは1つも使っていません。いまは1台で完結していて、ネットに出ません。

当日も同じです。会場はテザリングなので、頭脳が自宅にあると 回線が切れた瞬間に会話が死にます。机の上で完結させます。

自宅の Mac Studio は退避先。think-url 1行で行き先が変わるので、 「じゃあ自宅に投げてみます」をその場で実演できます。

落ちたときにどうなるか

スタックチャンが誰を見に行くかは、本体の設定ではなく 同じLANで名乗っている機械（mDNS）で決まります。 名乗る／名乗らないの判断は、Mac Studio だけが持ちます。 両方が譲り合うと、誰も名乗らない事故が起きるためです。

A / 平常

MacBook が居る

MacBook が無条件で名乗る。空気を読みません。 同じLANなので踊りが低遅延で回ります。

B / 退避

MacBook が落ちた

Mac Studio が macbook.local:8765 を10秒ごとに叩いていて、 連続3回（30秒）届かなければ名乗り始めます。 復帰は2回で取り下げ ── 上下で回数を変えて、バタつきを止めています。

C / 最後の砦

どちらも居ない

本体の fallback_url が自宅のトンネルを向いています。 外を一周してでも繋がる形。ただし遅い。

MacBook が止まったときどうなるかなぜ
身体（首・表情・LED）生きる Mac Studio も同じコードを持っているから
会話生きる むしろ Mac Studio が本籍
背景スクリーン生きる iPadがURLを開き直せば繋がる
踊り死ぬ DJ機材がMacBookに挿さっているから。MIDIの供給元が消える

⚠️ この退避（B）は、まだ実装も実測もしていません。 設計は docs/master-and-hybrid.md に置いてあります。 切り替わるのは「次の再接続」なので、意図的に切り替えるには本体の再起動（RST短押し）が要ります。
