ファームを選ぶ、という
いちばん大きな分かれ道

スタックチャンは、箱から出した瞬間から喋ります。とてもよくできています。 ただ「その声がどこへ行くか」は、ファームで決まります。 5つ調べて、1つ選びました。その理由を置いていきます。

2026-09-29 Crypto Cafe and Bar ／ 出典 docs/00-concept.md §5–§7

01 — 選択肢ファームは5つある

どれが正解という話ではありません。何を大事にするかで変わります。 リモートで使いたいのか、手軽さを取るのか、声を外に出したくないのか。

ファームどんなもの遠隔声の行き先手間
① 出荷時（XiaoZhi）既定 ノーコード。アプリだけで完結する クラウド完結 海外のクラウド最小
② xiaozhi-esp32-server 接続先を自前サーバーに向ける できる 自前大
③ 元祖 stack-chan ブラウザだけで書き込める。教材として一番きれい 概念が薄い ほぼ出ない中
④ xangi-stackchan PCが頭脳。USB直結でフルローカル できない ほぼ出ない中〜大
⑤ stackchan-mcpこれにした ②のフォーク＋MCPゲートウェイ できる 自前大

02 — 出荷時ファームよくできている。だから、知っておく

けなす話ではありません。体験としては、いまでもこれが一番速い。 ただ、知らずに使うのと、知って使うのは別です。

良いところ

  • 買ってすぐ喋る。アプリだけで完結する
  • 速い。自前で組むと、たいてい負ける
  • 表情・モーション・ダンス・ESP-NOW が最初から入っている
  • アプリ経由のアバター／監視カメラ、アプリストア、OTA
  • Home Assistant の MCP にも繋がる

気をつけること

  • 音声認識・思考・音声合成はすべて海外のクラウドで処理されます
  • 通信先は深セン・香港のバックエンド
  • セットアップに利用規約の提示も承諾もありません
  • 会話の流れでカメラ撮影が起き、画像も送られます
  • ウェイクワードは Hi, StackChan 固定。モデルはアプリの選択肢内
規約には「入力された内容を無償・全世界・永続的に使ってよい」とあります。 モデルの改善、研究、宣伝、マーケティングを含みます。 規約自体は普通です。問題は、同意の動線が無いこと。

人前でデモするなら、説明責任はこちら側に来ます。 逆に言えば、これは「AIデバイスのプライバシー」の生きた教材になります。

03 — 選んだ理由体験を捨てずに、頭脳だけ動かせるから

②と⑤の系統は、そもそも「WebSocketで遠くのサーバーに繋いで喋る」のがプロトコルの前提です。 だから接続先のURLを差し替えるだけで、頭脳の置き場所を変えられます。無理をしていません。

⑤ stackchan-mcp を選んだ3つの理由

  • K151専用のボード定義がある。サーボ・LED・タッチ・カメラがそのまま動く
  • MCPゲートウェイになっている。Claude Code から首振り・撮影・表情を直接呼べる ＝開発が驚くほど速い
  • 出荷時の体験を保ったまま、頭脳だけ自分の側へ移せる

捨てた理由

  • ③ 元祖 — 教材としては一番きれい。ただ遠隔の概念が薄い
  • ④ xangi — USB直結なので遠隔ができない。宅内据え置きなら最高
  • ①は、上のとおり
⑤は②の代わりではなく、重ねるものです。 そして全部 OSS。読めるし、直せるし、フォークできる。 だから「自分の場合の構成」を作れます。今日話すのも、唯一解ではなく僕の場合です。

04 — MCPという入口ロボットが、AIの道具になる

MCP は「道具の並べ方と呼び方」だけを決めた規格です。 これに対応していると、Claude Code から実機の機能をそのまま呼べます。

05 — いまの形結局どうなったか

ロボットは入口と出口だけ。考えるのも、声を作るのも、光らせるのも、全部Macの中です。

これが今日いちばん持ち帰ってほしい考え方です。
「中にAIが入っているロボット」だと思うと、買ったものが天井になります。 入口と出口だと思うと、頭脳は自分で選べます。 今日のこれも、明日には別のモデルに差し替えられます。
