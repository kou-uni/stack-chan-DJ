# 遠隔ワークベンチ — 家に置いたまま、外から作る

**結論：可能。** Mac Studio にスタックチャンを常時USB接続しておけば、
外からファーム書き換え・シリアルログ・設定変更まで全部できる。
**詰みポイントは1つだけ**で、それはスマートプラグで回避できる。

---

## 常設構成

```
外出先 ──Tailscale──▶ Mac Studio（常時起動・スリープ禁止）
                        ├─ USB-C（足側）──── スタックチャン   書き込み / シリアル
                        ├─ USB ──────────── Webカメラ        首が振れたか目視する用
                        └─ スマートプラグ ── USBハブの電源     ★遠隔ハードリセット
```

操作系は3つ。用途で使い分ける。

| 手段 | 何に使う |
|---|---|
| Claude Code Remote Control | コードを書く・直す |
| SSH over Tailscale（+ tmux） | `idf.py flash` などの長い処理 |
| 画面共有 | M5Burner のようなGUIツール |

---

## 遠隔でできること

- `esptool` / `idf.py flash` による書き込み
  ESP32-S3 は USB-Serial-JTAG を持つので、**esptool が DTR/RTS で自動リセットしてブートローダに入る**。
  通常は物理ボタンに触らず焼ける
- シリアルモニタでブートログを読む
- サーバー（xiaozhi-esp32-server）の再起動・設定変更
- stackchan-mcp の `take_photo` で**本体のカメラから部屋を見る**
- `move_head` / `set_led` を叩いて、Webカメラ越しに動作確認

## 遠隔でできないこと ＝ 唯一の詰みポイント

**自動リセットが失敗したときの「RST 3秒長押し」（ダウンロードモード）。**

書き込み失敗でブートループに入り、かつ自動突入も効かない状態になると、
手が届かない限り復帰できない。

### 手当て（この3つで実質潰れる）

1. **スマートプラグでUSBハブごと電源を落として入れ直す**
   ほとんどの固まりはこれで戻る。SwitchBotプラグを1個買っておく
2. **焼く前に出荷時ファームのバックアップを取っておく**（`M5Burner` / `esptool read_flash`）
   帰宅後に確実に戻せる状態を作ってから、遠隔での実験を始める
3. **ケーブルは足側に挿してテープで固定**
   首が回るので、頭側だと自分で引き抜く

---

## そのほかの落とし穴

| 落とし穴 | 手当て |
|---|---|
| Mac がスリープして全部死ぬ | `scripts/keep-awake.sh` を常駐 |
| 書き込み中に接続が切れて中断 | **必ず tmux 越しに実行**。セッションが切れてもプロセスは生きる |
| **音の確認が遠隔では一番難しい** | Webカメラのマイクで拾う。「喋ったか」はLEDが青くなるかで代用 |
| サーボが暴れて机から落ちる | 台に固定し、周囲を空ける。落下は遠隔では絶対に直せない |
| USBのバスリセットで見失う | ハブを噛ませる。ポート番号を固定して `ls /dev/cu.*` を記録 |

---

## 始める順番

1. 帰宅時に：出荷時ファームのバックアップを取る
2. 帰宅時に：Webカメラを本体に向けて固定、スマートプラグを噛ませる
3. 帰宅時に：外から1回、**焼き直して戻す**のを通しでやる ← ここまでが「保険が効いている」状態
4. 以降は外から自由に実験してよい

**3 を家にいるうちに1回通しておくこと。** ここを飛ばすと、外で詰んだときに何も分からない。
