# NFC 受付 — かざすと名前を呼ぶ

**2026-09-26 に作った。仕様は `tests/test_nfc.py`、本体は `app/dj/nfc.py`。**

```
  M5Stack RFID 2 Unit（WS1850S）── Grove Port A（赤・I2C 0x28）── 実機
                                                                    │ i2c_write / i2c_write_read（MCP）
                                                                    ▼
  Mac:  Rc522（読む） → Greeter（誰か・何回目か） → 顔（happy）・光（白→ミント）・声
```

**ファームは触っていない。** Port A を叩く汎用 I2C ツールがファームにあるので、Mac から WS1850S を直接読む。
実機は UID を返すだけで、**名前・回数・挨拶は Mac 側**。

## 使い方

```bash
./.venv/bin/python scripts/nfc_enroll.py --scan          # Port A に 0x28 が見えるか
./.venv/bin/python scripts/nfc_enroll.py                 # かざす → 名前を打つ → 保存（繰り返し）
./.venv/bin/python scripts/nfc_enroll.py --add 043b33 うに   # 鍵が分かっていれば1行で
./.venv/bin/python scripts/nfc_enroll.py --list          # 名簿を見る
```

- 名簿は **`event/rec/guests.toml`**。★人名なので git に入れない。**当日は MacBook へ手で運ぶ**（checklist）
- 来訪記録は `event/rec/visits.jsonl`（回数の元。git に入れない）
- console が動いていれば自動で受付が動く（`config.toml` の `[nfc]`、`nfc-poll-s = 0` で止まる）
- 反応：1回目「いらっしゃい、〇〇さん！」／2回目「また来たね」／3回目〜「今日は N 回目だね」／
  未登録「はじめまして！名前、まだ聞いてないや」。**同じ台詞は続けて出さない**

## 実測で決めたこと（2026-09-26）

| | 値 | なぜ |
|---|---|---|
| 1往復（MCP→Wi-Fi→I2C） | **15〜50ms** | これが全ての単位 |
| カード無しの1周 | **≈210ms** | 8往復。誰もいないなら粘らない |
| 読めた周 | **≈400ms** | WUPA＋CL1 の2段 |
| 置きっぱなしの検出率 | **≈48%/周** | RF の結合が限界。0.4秒周期なら 2秒で 9割拾う |
| 次に拾えるまで | 中央 0.8秒・最大 3秒 | |
| debounce | **12秒** | 6秒だと拾えない間が空いて「はじめまして」を二度言った |

### ★7バイトのカードは、先頭3バイトを鍵にする

NTAG 系（よくあるシール・カード）は UID が 7 バイト。読み切るには WUPA→CL1→SELECT→CL2 の4段が要るが、
**1段が 250ms もかかる**と、段が進むほどカードが脱落し、**読み切れるのは1割以下**だった。
HALT の有無でも電界リセットでも変わらない（CL1 46% / 37%）。**手順を短くするしかない。**

→ **CL1 で取れる先頭3バイト（例 `043b33`）を鍵にする。** 名前を呼ぶにはこれで足りる。
3バイトは他のカードと重なりうるので、**登録時に同じ鍵へ別の名前を入れようとしたら弾く**。
読み切る `read_full_uid()` は登録用に残してある。

### 実機で初めて分かった罠（偽物のテストでは緑だった）

| 罠 | 直し |
|---|---|
| `gw.call` の返事は dict ではなく `CallToolResult`（`content[0].text` に JSON） | `McpBus.unpack` |
| 前の Transceive を止めずに FIFO に書くと `WrErr(0x80)`。何も送れない | 送る前に `Idle` |
| REQA だと、一度選んだカードが答えなくなる | 検出は WUPA |
| `00000000` が BCC 込みで通る | 全ゼロは捨てる |
| `Presence` の優先表に無い種類は例外。**顔・光・声はその後ろにあった** | `PRIORITY` に `nfc`。本物の Presence で試す試験を追加 |

**偽物は「手順が壊れていない」を守るためのもの。「実機で動く」は実機でしか分からない。**

## 実機を再起動しても生き続ける（NfcSupervisor）

実機を再起動すると Unit も電源が切れ、アンテナ OFF の既定に戻る。**例外は出ない。ただ何も読めなくなる。**
しかも gateway は電源断を検知できない（FIN が来ない。古い接続は 18 秒後にタイムアウト）。

- 起動時に Unit が居なくても諦めない（5秒ごとに繋ぎ直す）
- console の `init_device`（実機が戻った）から知らされたら初期化し直す
- **25周ごとにアンテナを点検**し、落ちていたら初期化し直す（電源断はこれで拾う）
- 失敗が5回続いても初期化し直す
- **MCP の1呼び出しに3秒の時限。** 実機が消えた瞬間の呼び出しが返らず、見張りごと固まった（実測）。
  固まるより失敗のほうがいい。失敗は数えられて、初期化し直しに繋がる

常駐4つ（OTAスタブ・VOICEVOX・gateway・console）は `RunAtLoad` / `KeepAlive`。**Mac の再起動もまたぐ。**
