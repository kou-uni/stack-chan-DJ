### 当日の狙い：スタックチャンがサブ講師になる（2026-09-10）

> **AIについて学ぶ会で、AIが教える。この構造自体が教材になる（メタ認知）。**
> **そして、会話機能の価値がここで具体になる。**

**解く問題：** もくもくタイムは講師が1人なのに質問が同時多発する。
25分あっても10人なら1人2分半。**待っている間、手が止まる。**

| 層 | 誰が | 手段 | 特性 |
|---|---|---|---|
| **層1** | 参加者自身の Claude Code | 文字 | **人数分ある。スケールする**（C15 のリポジトリを読ませる） |
| **層2** | **スタックチャン** | **音声・物理** | 1体。**体験としての価値。**P3 の実演そのもの |

**★音の条件はむしろ有利。** もくもくタイムは DJ が鳴っていない＝
**音声が通る唯一の時間帯**。時間割で解ける。

> 出典：本人（2026-09-10）「音声のAIエージェントを作っておいて、
> そのエージェントに相談をかけていくと自律的に対応してくれる体験を提供したい。
> 僕のサブ講師というかAIを作れるといいな。そのうちの一つはスタックチャンがその役割を担う」

### データループ（2026-09-10）

> **相手の課題を解決することと、質問を集めることは、同じくらい大事。**

**理由：** 答えられなかった質問が、**次の教材そのもの**になる。
どこで詰まるかは、こちらの想像ではなく**実際の質問**でしか分からない。

| # | 中身 |
|---|---|
| **P9** | エージェントは**質問を収集する**。何を聞きたかったか、どこが分からなかったか |
| **P10** | **適合性を評価する。**自分の知識で答えられたか／的外れだったか／範囲外だったか |
| **P11** | 集めたものを**教科書とスキルに還す**。これを回し続ける仕掛けを、最初から作り込む |

**★この会でやるからには、同意の動線を必ず作る。**
出荷時ファームを「**同意の提示も承諾もない**」と批判する会で、
こちらが黙って集めたら矛盾する。
**逆に、同意を取って集めるところまで見せれば、それ自体が教材になる**（B3 と対になる）。

### データ主権と、返し方（2026-09-10）

> **集める前に、返す。**

| # | 中身 |
|---|---|
| **P12** | **質問と、そこから分かった特性は、まずその人に返す。**これが既定 |
| **P13** | イベント側が今後に生かしてよいかは、**最後に同意を取る。同意した分だけ**受け取る |
| **P14** | 返し方は**面白く。**質問の傾向から「あなたの特性」を診断して返す（ゲーミフィケーション） |
| **P15** | **情報が足りなければ「評価対象外」と正直に言う。**ここが占いとの決定的な差 |
| **P16** | **使うほど精度が上がる。**持ち帰ったあとも効く |

**★同意の順序が逆になっているのが要点。**
「集めさせて → 使わせて」ではなく「**あなたに返す → よければ共有して**」。
出荷時ファームの批判（B3）と対になる実演。

#### 診断の設計（提案・未確定）

- 軸は**「あなたのDJスタイル」＝ AIとの向き合い方**にすると、哲学（P2/P4）と直結する
- **質問の「形」から取る**（内容ではなく形なので、少ない質問でも判定できる）

| 訊き方 | タイプ |
|---|---|
| 「なぜそうなるの？」 | 仕組みから入る人 |
| 「どうすればできる？」 | 手を動かして掴む人 |
| 「何ができるの？」 | 発想が先に来る人 |
| 「それ危なくない？」 | 足場を固める人 |

- **16タイプは90分では薄すぎる。**1人が投げる質問は数個。4タイプでも「対象外」は出る
- MBTI 系の名称は商標。**独自の軸にする**
- **★バーナム効果に自分から触れる。**「当たってると思いました？ なぜそう感じるかまで説明します」
  → ゲーミフィケーションが教材になる（AIの信頼性の話と繋がる）

### 当日の見せ方（2026-09-10）

**人間が DJ、AI が演者。この役割分担を「実演して見せる」。**

| 人間がやること | AI がやること |
|---|---|
| **選ぶ・混ぜる・止める（統制）** | ドキュメントを読む／作業する |

- **もくもくの前に、この持っていき方を説明する**
- 抽象的な比喩（P2）を、**その場で手を動かす形**にする

#### もくもくタイムは二本立て

| | 誰が | 何を |
|---|---|---|
| **もくもく派** | 自分で進めたい人 | エージェントと対話しながら作る |
| **ディスカッション派** | 話したい人 | **人間同士**で「こんなことできないか」を話す |

> **Bar に集まる意味は人と話せること。**黙々を強制しない（本人 2026-09-10）

#### 音声と文字を分けて設計する

**★文字が多すぎると、音声はずっと喋り続けることになる。工夫が要る。**

| | 手段 | 長さ | 役割 |
|---|---|---|---|
| 各自のエージェント | **文字** | 長くてよい（読み飛ばせる） | 手順・深い話 |
| **スタックチャン** | **音声** | **短く。**読み飛ばせない | **受付と振り分け** |

**提案（未確定）：** スタックチャンは短く答え、深い話は
**「手順は君のエージェントが持ってる」と各自のエージェントに振る。**
→ 音声が短く済み、C ブロックで渡したものを使わせる導線になり、
**物理的にそこに居る意味**（全体を見て誰に何を渡すか判断する）が出る。

### この哲学が否定するもの

- **教科書を「同じものを作る手順書」にすること。** 再現手順は土台で、目的は**自分のものが作れること**
- **DJ を「見せ場」扱いすること。** DJ は**主題**。入力側の象徴
- **会話やハンズオンを削ること。** 人格カードは DJ と**同じ主題の裏返し**（素材は共通でも、あなたが出る）
