## 0. 全体像 — 3つの系統

**この3つは別のもの。混ぜない。**

| 系統 | 何をする | 頭脳 | 与件 |
|---|---|---|---|
| **① 会話** | 声を聞いて、考えて、喋る | 自宅 Mac の LLM | C1 ★ |
| **② 演技** | 音・触覚・視覚に体で反応する | console（母艦） | C3〜C5 |
| **③ 参加者** | スマホから人格を投げる・操作する | Web（母艦） | C2 ★ / C6 |

```
                        ┌──────────── ① 会話 ────────────┐
  参加者の声  ──▶  実機  ──▶  gateway  ──▶  xiaozhi-server ──▶ Ollama
                     ▲                          │
                     │                     人格プロンプト
                     │                          ▲
                     │                          │
  参加者のスマホ ─────┼──────────────────────────┘   ③ 参加者
       （QR）        │      ペルソナボード（Web）
                     │
                     └──  console  ◀── DDJ-FLX2 / タッチ / カメラ   ② 演技
                           （首・表情・LED）
```

### 系統をまたぐ約束

**★実機の状態を書くのは、依然として1人だけ。**（§4 I1）
会話が表情を変えたいときも、**`Presence` に宣言する**。実機を直接叩かない。

| 系統 | 実機への影響 | どう渡すか |
|---|---|---|
| ① 会話 | 喋る・表情 | 感情タグ → `Presence.overlay()` |
| ② 演技 | 首・表情・LED | `Presence` / `HeadArbiter` |
| ③ 参加者 | 人格の差し替え | **実機に触らない。**頭脳側のプロンプトを変える |

**③ が実機を直接触らないのが要点。** 参加者の入力が実機に届く前に、必ず頭脳を経由する。

## 1. 考え方

**命令しない。「あるべき姿」を宣言し、反映役が1人で書く。**

```
    出来事                あるべき姿                実機
  ─────────           ─────────           ────────
  PLAY を押した   ──▶                    ──▶  set_avatar
  曲がきた        ──▶   Presence          ──▶  set_blink
  撫でられた      ──▶  （状態の一式）      ──▶  beat_mode_update
  つまみを回した  ──▶                    ──▶  首・LED のストリーム
                          │
                     Reconciler（唯一の書き手・差分だけ送る）
```

こうすると、**順番の事故が構造的に起きない**。
誰がいつ何を叩いたかを追う必要がなくなり、見るのは「いまのあるべき姿」だけになる。

## 2. 状態モデル

状態を**3層**に分ける。混ぜない。

### ① モード — 人が決める

| 状態 | 意味 | 顔 | LED |
|---|---|---|---|
| `OFF` | 音に反応しない | idle | 青（暗め） |
| `DJ` | 音に反応する | happy | マゼンタ |

**遷移はこれだけ。**

```
  OFF ──[PLAY]──▶ DJ
  DJ  ──[MASTER]──▶ OFF
  DJ  ──[曲が来ないまま N 分]──▶ OFF
```

### ② 活動 — 音が決める（DJ のときだけ）

| 状態 | 入る条件 | 抜ける条件 |
|---|---|---|
| `待機` | 既定 | 音量が下限を超え、拍がある |
| `計測中` | 踊りの合間、周期的に | 1.5秒経過 |
| `踊り` | ノリが下限を超えた | ノリが下限×0.7 を下回る |

**★`計測中` は首を止める。** サーボ音は音楽の13倍あり、動いている間の観測は使えない。
**★止める閾値は始める閾値より低い。** 同じ値だと境目で点滅する。

### ③ 出来事（オーバーレイ）— 一時的に上書きする

**必ず期限を持つ。期限のない上書きは作らない**（消し忘れが必ず起きる）。

| 出来事 | 顔 | 続く時間 | 優先 |
|---|---|---|---|
| つまみを回している | embarrassed | 触っている間＋余韻 | 1（最優先） |
| 撫でられた | 設定の顔 | 3秒 | 2 |
| 計測中 | embarrassed | 1.5秒 | 3 |
| サビ | surprised | 2.5秒 | 4 |
| 歓声 | happy | 1.5秒 | 5 |
| 顔を見つけた | happy | 2秒 | 6 |

同時に複数あれば**番号の小さい方が勝つ**。
どれも無ければ、①②から決まる顔になる。

## 3. 状態 → 実機（唯一の対応表）

`Presence` がこの表を計算し、`Reconciler` だけが書く。

> **gateway 側の beat mode にも首とLEDを動かす機能がある。使わない。**
> `beat_mode_start` はそれを有効にして始まるので、反映役が毎周期切り直す。
> 実機を動かすのは console のストリームだけ、という一本化を守るため。

| 実機の状態 | 決め方 |
|---|---|
| **表情** | オーバーレイの最優先 → 無ければ 活動（踊り=happy）→ モードの顔 |
| **瞬き** | **止めるのは「顔を作っているとき」だけ**（オーバーレイ有り or 踊り）。それ以外は必ず ON |
| **beat の踊り** | **常に切る。** 首を動かす人が2人いてはいけない |
| **首** | `HeadArbiter`（つまみ > キメのポーズ > 踊り）。無ければ送らない |
| **LED** | `LedState`。モードで色、活動で模様 |

## 3.4 会話が来たときの表情（① の受け口）

**会話の返答に感情タグを付けさせ、それを上書きに変換する。**

```
  LLM の返答  "(Happy) ええ感じやん"
                 │
                 ▼
  Presence.overlay("talk", "happy", seconds=返答の長さ)
```

- タグは6種（Neutral / Happy / Sleepy / Doubt / Sad / Angry）。**指示は最小限にする。**
  役割を増やすと失敗しやすい（00-concept §12）
- **喋っている間は瞬きを止める**（既存の規則がそのまま効く）
- タグが無い・知らないタグなら、**上書きしない**（既定の顔のまま）

**★会話が実機を直接叩かない。** ここを守れば、踊りと会話が競合しない。

## 3.5 配置 — どの Mac が何を動かすか

**★ここが設計文書に無かったので、丸ごと忘れた（2026-09-09）。**
状態の設計だけ書いて、それが**どこで動くか**を書いていなかった。

| | 自宅 | 会場 |
|---|---|---|
| gateway | Mac Studio | **MacBook** |
| console（演技） | Mac Studio | **MacBook** |
| DDJ-FLX2 | Mac Studio | **MacBook** |
| **頭脳（会話・LLM）** | **Mac Studio** | **Mac Studio（留守番）** |
| ペルソナボード（Web） | Mac Studio | **MacBook**（会場のスマホから届く先） |

**★頭脳だけは、会場でも自宅に置いたまま。** これが主張 B1 の実体。
会場から自宅までの往復を、Tailscale Funnel が通す。
「いま自宅まで往復しています」が説明としてそのまま使える（run-of-show 0:30）。

**DJ機材は USB。だから console は DDJ が刺さっている Mac でしか動かない。**
会場に持っていくのは MacBook なので、**MacBook で全部動く必要がある**。

実機がどちらを見るかは `websocket.url` を**空にした mDNS** が決める。
同じ LAN にいる gateway を自動で見つけるので、**本体に触らずに切り替わる**。

```
  実機 ──[mDNS で探す]──▶  同じ LAN に居る gateway
                            自宅なら Mac Studio / 会場なら MacBook
```

### 守ること

- **その機械にしか無い値をコードに書かない。** パス・IP・インターフェース名・シリアルポート。
  設定に出す（`config.toml` / `.env.gateway`）。
- **一から立ち上げる手順を1本にする**（`scripts/setup.sh`）。
  依存は `requirements.txt` に固定する。**これが無いと別の Mac で再現できない。**
- 常駐の設定（launchd の plist）は**実行時にパスを埋める**。固定で書かない。

`tests/test_portability.py` が検査する。

## 5. 起動と停止

### 起動

```
  ① gateway に繋ぐ
  ② 実機が来るまで待つ          常駐なら無限に待つ
  ③ 表情データを読み込む         電源で消えるので毎回
  ④ 首とLEDのストリームを購読
  ⑤ beat mode を開始            ★踊りを有効にして始まる
  ⑥ モードを確定（既定 OFF）     ★⑤に上書きされないよう必ず最後
```

**この順番は `init_device()` にしか書かない。** 起動時も、実機が戻ったときも同じ関数を通る。

### 停止

```
  ① beat mode を止める          先に音を聴くのをやめる
  ② ストリームの購読を解除
  ③ 首を正面へ
  ④ 待機の顔へ
  （サーボの脱力は実機の自動脱力に任せる）
```

**8秒で打ち切る。** 応答しない相手を待って止まらなくなる方が困る。

### 実機が消えたとき

見張り役が5秒ごとに確認し、`居ない → 居る` に変わったら `init_device()` をやり直す。
**console は立ち上げ直さない。**
