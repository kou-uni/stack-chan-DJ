# スタックチャン 構想メモ

最終更新：2026-09-02

---

## 0. ゴール

**自宅の Mac Studio を頭脳にして、外に持ち出したスタックチャンをネット越しに動かす。**

これ自体がデモの中身。単に「AIロボットが喋る」ではなく、
「エッジ端末が自宅のローカルLLMと繋がっている」ことを見せる。

副次的に得られるもの：

- 記憶が続く（「昨日の話だけど」ができる）
- 会話データが海外クラウドに出ない
- 会場から自宅の家電を操作できる

---

## 1. スタックチャンとは

ししかわ（石川真也）氏が2021年に公開した手のひらサイズのオープンソースロボット。
外装・基板・ファームウェアが Apache-2.0 で公開。
2026年春に M5Stack が公式キット（SKU: K151 / K151-R）を製品化。

「スタックチャン」「ｽﾀｯｸﾁｬﾝ」は石川真也氏の登録商標。

### ハードウェア（K151）

| 項目 | 内容 |
|---|---|
| コントローラ | M5Stack CoreS3（ESP32-S3） |
| サーボ | フィードバック付き2基（横360°連続回転／縦90°） |
| バッテリー | 550mAh |
| カメラ | GC0308 / 0.3MP（640x480） |
| マイク | デュアル |
| センサ | 近接・環境光、9軸IMU、3ゾーン容量タッチ（Si12T） |
| その他 | 12x RGB LED、NFC、赤外線送受信、Grove x3（HY2.0-4P） |

## 2. UX としての価値

PCのAIは「開くもの」、スタックチャンは「そこにいるもの」。

- 起動しなくていい。「ねぇ」で始まる
- 向こうから話しかけてくる（独り言モード、時間トリガー）
- 手が塞がっていても使える
- その場の全員が同時に話しかけられる
- 体で返事をする（うなずき、首かしげ、表情）
- 家とつながる

### 期待値のズレやすい点

- **記憶が続かない**（実機単体では前日の会話を覚えていない）
- **常時待機ではない**（タップや顔検出がきっかけ）
- **聞き取り時間が短い**（長い相談より短いやりとり向き）

実感としては「**ペットの見た目をした、ネットワーク端末**」。
かわいさで毎日触られる → だから通知や操作の入口として機能する、という順番。

## 3. アーキテクチャの考え方

スタックチャンは**頭脳ではなく I/O ゲートウェイ**。
センサ入力とHTTPを受けて、音声・表情・モーションという人間向け出力に変換する周辺機器。

### 2系統

- **A：ファーム自身がオーケストレータ** — ESP32が直接APIを叩く。手軽だがRAMとTLSが上限、記憶を持てない
- **B：ホストが頭脳、実機はドライバ** — PC側が判断し、`FACE / MOVE / WAV` 等の命令だけ流す ← **今回はこちら**

### 3層モデル

| 層 | 内容 | 実装場所 |
|---|---|---|
| ① 反射層 | なでたら喜ぶ、起動時挨拶、独り言 | ファーム内（ネット不要） |
| ② ゲートウェイ層 | HTTP API、WebSocket | ファーム内 |
| ③ 頭脳層 | ルーティング、記憶、外部連携 | Mac Studio |

### ルーティングの原則

**確実性が要るものは自分で書く。曖昧な自然文だけLLMに投げる。**

全部LLMに任せると、朝の予定読み上げが気まぐれで失敗する。

| 置き場所 | 挙動 | 向くもの |
|---|---|---|
| 自分のコード | if文で決定論的 | 定時通知、センサー→反応 |
| LLM（Function Calling / MCP） | LLMが関数を選ぶ | 自然文の依頼、曖昧な指示 |

### トリガーの種類

| きっかけ | 例 |
|---|---|
| タッチ・頭なで | 会話開始、リアクション |
| 顔検出 | 音声認識の起動 |
| 特定の言葉・文脈 | Function Callingで機器操作 |
| 時間 | 独り言、朝の声かけ |
| 外部からのHTTP | 通知、監視アラート、Slack連携 |

## 4. やりたいこと（想定ユースケース）

- カレンダー連携：朝の予定読み上げ、直前リマインド、「今日の予定は？」に応答
- 家電操作：SwitchBot / Home Assistant 経由
- 筋トレの声かけ：褒める・催促する

### 筋トレ機能のトリガー案

- スマート体重計の記録更新を検知
- SwitchBotの開閉センサー（器具・部屋のドア）
- 自己申告（「終わった」と言うだけ）← **一番確実で一番早い**
- 時間トリガー（夜になっても記録がなければ声かけ）

褒め方・催促の強さは、人格プロンプトに書くだけ。実装的にはプロンプト設計。

**なぜ効くか**：通知アプリの「筋トレしましょう」は無視しても罪悪感ゼロ。
机の上のものが顔を上げて言ってくると無視しづらい。**催促の主体が物理的に存在する**ことに意味がある。

## 5. ファーム比較

| | 概要 | リモート | 課金 | プライバシー | 設定の手間 |
|---|---|---|---|---|---|
| ① 出荷時（XiaoZhi） | ノーコード、アプリで完結 | クラウド完結 | 無料 | **高リスク** | 最小 |
| ② xiaozhi-esp32-server | 接続先を自前サーバーに | **可** | 無料 | 低 | 大 |
| ③ 元祖 stack-chan（JS） | ブラウザで書き込み、MOD | 概念が薄い | 無料 | ほぼなし | 中 |
| ④ xangi-stackchan | PCが頭脳、USB直結 | **不可** | 無料化可 | ほぼなし | 中〜大 |
| ⑤ stackchan-mcp | MCPゲートウェイ | **可** | 無料 | 低 | 大 |

### ① 出荷時ファーム

- できる：AI会話、表情・モーション、ダンス、ESP-NOW、アプリ経由のアバター／監視カメラ、アプリストア、OTA、Home Assistant MCP
- 制約：ウェイクワードは "Hi, StackChan" 固定、AIモデルはアプリの選択肢内、EzData未実装
- AIエージェント設定変更後は本体の再起動が必要

### ③ 元祖 stack-chan

- Chrome/Edge から**ブラウザで書き込める**（Moddable SDK も ESP-IDF も不要）
- MOD Gallery、ブロックエディタあり
- **教材としては一番きれい**

### ④ xangi-stackchan（karaage0703）

- `STATUS / VOLUME / WAV / FACE / MOVE / CAPTURE` の自前プロトコル
- なでなで検出（Si12T 3ch）、12 RGB LED状態表示（thinking / talking / error）、カメラ、音声対話モード
- faster-whisper（STT）+ piper-plus / VOICEVOX（TTS）でフルローカル無料構成が可能
- **USB直結のためリモート不可** ← 今回の要件で脱落。宅内据え置きなら最高

### ⑤ stackchan-mcp（kisaragi-mochi）

- xiaozhi-esp32 のフォーク。`firmware/main/boards/stackchan/` に **K151専用ボード定義**
- Claude Code / Claude Desktop から首振り・カメラ撮影・タッチ読み取り・表情切り替えを呼べる
- `remote-access.md` に **Tailscale Funnel によるLAN外アクセス手順**
- `architecture.md`（構成図、ツール名マッピング）、`firmware-sync.md`

## 6. プライバシー：出荷時ファームのリスク

### 確認された事実

- STT・LLM・TTS はすべて **XiaoZhi AI のクラウド**で処理される（ソースコードによる）
- 通信先：StackChan専用バックエンド（**中国・深セン**）、XiaoZhi AI（**香港**）、M5Stack EzData（**香港**）、NTP
- **セットアップ動線に利用規約の提示も承諾もない**
- **会話の流れでカメラ撮影が起き、画像もクラウドに送信される**
- M5Stack 側も「xiaozhi公式に接続、ポリシーは同じ」と回答

### 利用規約 6.1.3（要旨）

ユーザーが入力・生成・公開・拡散した情報内容について、
**無料・全世界・永続的・譲渡可能・サブライセンス可能な利用権**を XiaoZhi 側に付与。
保存・利用・複製・修正・編集・公開・展示・翻訳・配布・派生作品の作成が可能で、
**モデル最適化、研究、宣伝、マーケティング、ユーザー調査**を含む。

### 補足リスク

GitHub の公開コードと実機のバイナリが同一である**保証がない**。
ビルド・リリースのパイプラインが非公開で、検証が困難。

### 対策

- 物理カメラカバーを貼る
- 使わないときは電源を切る
- ゲストネットワークに隔離
- **学生の前でデモするなら、その場の声と顔が送信されうることを説明する**
  - 同意の導線がない以上、説明責任はこちら側に来る
  - 逆に「AIデバイスのプライバシー」の生きた教材にできる

## 7. 構成（本命）

```
会場：スタックチャン + iPhoneテザリング（2.4GHz）
  ↓ WebSocket
Tailscale Funnel（HTTPS公開）
  ↓
自宅 Mac Studio：xiaozhi-esp32-server + LM Studio / Ollama
  ＋ 記憶DB、カレンダー、SwitchBot
```

- **ベースファーム**：stackchan-mcp の xiaozhi-esp32 フォーク（K151ボード対応）
- **サーバー**：Mac Studio の xiaozhi-esp32-server + LM Studio / Ollama
- **公開**：Tailscale Funnel
- **家電操作**：MCPゲートウェイ経由

### なぜこの構成か

②の系統は「WebSocketで遠隔サーバーに繋いで喋る」のがプロトコルの前提。
接続先URLを差し替えるだけで外から自宅を向かせられる。無理をしていない。
出荷時ファームの体験（ウェイク、表情、モーション）を維持したまま頭脳だけ移せる。

⑤は②の代替ではなく**重ねるもの**。K151固有のサーボ・LED・タッチ・カメラ対応と、
Tailscale Funnel の手順書を持っているのが理由。

### 未検証の懸念

自前ビルドすると **StackChan World アプリとの連携が効かなくなる可能性**が指摘されている。
アプリ経由のアバター表示・監視カメラ機能を諦められるか要判断。

## 8. 構築手順

1. Mac Studio に `xiaozhi-esp32-server` を Docker で立てる
2. LM Studio か Ollama を入れ、**ローカルネットワーク提供をオン**
3. **宅内で完結動作を確認**← 第一関門
4. Tailscale を Mac に入れ、Funnel でサーバーを公開
5. スタックチャンの接続先URLを Funnel アドレスに変更
6. **テザリング経由で家の外から動作確認**← 第二関門

### 技術的注意

- ESP32側は WebSocket。**Funnel が ws を通せるか**が肝
- **Mac をスリープさせない**（`caffeinate` か省エネ設定）
- **接続先URLの切り替えを楽にしておく**（現地で戻せないと詰む）
- モデルサイズは応答速度と直結。往復遅延が乗るので小さめから
- 回線が **v6プラス（MAP-E）** のため、従来のポート開放は機能しない。トンネル前提
- **ESP32 に Tailscale は入らない**。Mac側を公開する方向になる

### 焼く前の必須手順

**StackChan World アプリか本体設定からアンバインドする。**
忘れるとペアリング不整合が起きる。

## 9. 物理・初期設定メモ

### USBポートは2箇所

どちらも給電・データ通信の両方に対応。

- **頭側** — CoreS3本体のUSB-C（電源ボタンの隣）
- **足の後方** — ベース基板側 ← **普段はこちら**（首が回るのでケーブルが引っ張られる）

頭側の出番はトラブルシュート時と、CoreS3の単体テスト。

### ボタン

| 操作 | 方法 |
|---|---|
| 電源ON | 左側USB-C隣の電源ボタンを短押し |
| 電源OFF | 同ボタンを6秒長押し |
| リセット | 底面microSD隣のRSTを短押し |
| ダウンロードモード | RSTを3秒長押し、隣のLEDが緑になったら離す |

### 初期設定（出荷時ファーム）

**SDカード不要。書き込み不要。APIキー不要。**

1. スマホに「StackChan World」アプリを入れる
2. M5Stackアカウントでログイン
3. 電源ON → 画面のガイドが始まる
4. Start → 本体から手を離して平らな場所に置く → Start → サーボテスト
5. アプリで「Add a new StackChan」→ BLEスキャン → 本体画面のIDと一致するものを選ぶ
6. 設定（デバイス名、AIエージェント、Wi-Fi）
7. OTAでファーム更新

### 引っかかりポイント

- **Wi-Fiは2.4GHzのみ**。5GHz非対応。キャプティブポータルも非対応
- **iPhoneテザリングはデフォルト5GHz** → 設定 → インターネット共有 → **「互換性を優先」をオン**
- デバイス一覧が出ないときは Bluetooth 権限を確認
- データ通信対応のUSB-Cケーブルを使う（充電専用だと書き込めない）
- 同梱の 1.25-4P 延長ケーブル（100mm）は用途が公式に明記されていない。
  分解・換装時の内部配線延長用とみられる。Grove（HY2.0-4P）とは別規格

### 工場出荷に戻す

2種類ある。

- **アンバインド** — アカウント紐付け解除、AIエージェント設定と会話履歴を削除。ファームはそのまま
- **M5Burnerで書き戻し** — 本当のファーム復元。他ファームを焼いた後でも戻せる

M5Burner v3 →「StackChan」検索 → **Only Official** にチェック → Download → 足側USB-Cで接続 → Burn。
ポートが出ないときはダウンロードモードへ。

**往復自由**なので、気軽に載せ替えてよい。

## 10. 外デモの実務

### 持ち物

- 本体、USB-Cケーブル、**モバイルバッテリー**（550mAhは小さい）
- 物理カメラカバー（プライバシー説明の小道具にもなる）
- iPhone 2台あると安心

### 前日までに

1. iPhone「互換性を優先」オン
2. iPhone名を英数字に変更
3. **テザリング経由の接続テストを完了**
4. ファーム更新を済ませる
5. 音量を上げる

### 当日

- **タップで起動**（ウェイクワードは騒がしいと拾わない）
- LEDの色を説明に使う：**緑＝聞いている、青＝喋っている、消灯＝待機**
- 触らせる（頭のタッチをなでる、振ると目が回る）
- プライバシーの話をする

### やらないこと

- 会場Wi-Fiに繋ぐ
- 連続タップ（ウェイクモードから抜ける）
- 電源が入った状態で首を手で回す（ハードが壊れる）

### 保険

M5Burner で出荷時ファームに戻せる状態にしておく。
落ちたら「今、自宅との接続が切れました。これがエッジとクラウドの違いです」と話に変える。

## 11. デモで映える要素

**掴み（ネット不要）**

- 名前を呼ぶ／近づくとこっちを向く
- 頭をなでると喜ぶ
- 手のひらに乗せる

**本命（人格ギャップ）**

- キャラ設定を振り切る（見た目のかわいさと口調のギャップ）
- 表情が変わる（喋る内容より顔が変わる方が伝わる）
- その場の人の名前を呼ばせる

**締め（物理的な結果）**

- スマート電球を1個持参して「電気つけて」→ 本当に点く
- カメラで実況させる
- 2体持っていく（AI同士で会話させる）

**最重要：触らせること。**
見せるだけのデモと、一人ひとりに話しかけさせるデモでは記憶への残り方が違う。

## 12. 応用テクニック（コミュニティ知見）

- **感情タグによる表情同期**（robo8080方式）：返答の先頭に `(Happy)` のように感情種別を付けさせる。
  Neutral / Happy / Sleepy / Doubt / Sad / Angry。ロールを増やすと失敗しやすいので指示は最小限に
- **Realtime API で音声→音声を直結**し、STT→LLM→TTSの多段遅延を潰す
- **ESP-NOW で複数体連携**（送信側の頭を手で回すと受信側も同じ角度に回る）
- **実機は薄く保つ**。ESP32側にロジックを入れるほど、デバッグのたびに書き込み直しになる
- **ライセンス確認**：M5公式リポジトリにGPL-3.0のSCServo_libが同梱されていた件が2026年5月に指摘され、
  翌日のv1.4.0でMITのFTServo_Arduinoに置換。配布物を作るなら依存確認は必須
