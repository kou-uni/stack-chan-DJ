# Day 1 — 出荷時ファームで動きを確認する

**今日のゴールは「動かすこと」ではなく「基準を取ること」。**
後で自前ファームに移したとき、何が良くなって何が失われたかを比べる物差しを作る。

所要 60〜90分（OTA更新の待ち時間込み）。

---

## ⚠️ 始める前に：今日から会話はクラウドに出る

出荷時ファームは STT・LLM・TTS すべて XiaoZhi のクラウド（深セン / 香港）で処理する。
**会話の流れでカメラのシャッターも切れて、画像も送られる。**

- 物理カメラカバーを先に貼る（無ければマスキングテープ）
- 機微な会話をしない。家族がいる部屋なら一言伝える
- 使い終わったら電源を切る

これは今日の作業の話であると同時に、**イベントで話すネタそのもの**。
→ [../event/privacy-notice.md](../event/privacy-notice.md)

## Phase 1. 電源を入れる（10分）

### USBは足側に挿す

ポートは2箇所あり、どちらも給電・データ通信に対応している。

- **足の後方（ベース基板側）← 普段はこちら。** 首が回るのでケーブルが引っ張られない
- 頭側（CoreS3本体）はトラブルシュート時と単体テスト用

### ボタン

| 操作 | 方法 |
|---|---|
| 電源ON | 左側USB-C隣の電源ボタンを**短押し** |
| 電源OFF | 同ボタンを**6秒長押し** |
| リセット | 底面microSD隣の RST を短押し |
| ダウンロードモード | RST を3秒長押し、隣のLEDが緑になったら離す（今日は使わない） |

### 手順

1. [ ] 足側に給電
2. [ ] 電源ボタンを短押し
3. [ ] 画面のガイドが始まる → **Start**
4. [ ] **本体から手を離して、平らな場所に置く** → Start
5. [ ] サーボテストが走る。首が動くのを見守る

⚠️ **サーボテスト中は絶対に手を触れない。** 電源が入った状態で首を手で回すとハードが壊れる。
⚠️ 机の端に置かない。動いて寄っていく。

## Phase 5. 基準を取る ★今日の本題

「動いた」で終わらせない。**後で自前ファームと比べるための数字と感触を残す。**
下の表を埋めながら触る。

### 会話まわり

| 項目 | 見方 | 記録 |
|---|---|---|
| 応答速度 | 話し終わってから声が出るまで何秒か。3回測る | |
| ウェイクワードの反応距離 | "Hi, StackChan" が通る距離 | |
| **騒音下での反応** | 音楽を流しながら試す ← **イベントで使えるかの判断** | |
| タップ起動 | 反応するか。連続タップでモードが抜けないか | |
| 聞き取り時間 | 何秒喋ったら切られるか | |
| 記憶 | 一度電源を切って「さっきの話だけど」が通るか（**通らないはず**） | |

### 体と表示

| 項目 | 見方 | 記録 |
|---|---|---|
| サーボ可動域 | 横は本当に360°連続で回るか。縦の範囲 | |

| **音量** | 最大にして、音楽をかけた状態で聞こえるか ← **Barで足りるか** | |

| 項目 | 見方 | 記録 |
|---|---|---|
| **バッテリー持ち** | 給電を外して何分保つか（内蔵550mAh） | |
| カメラが撮るタイミング | どういう流れでシャッターが切れるか（**プライバシーの話の実例になる**） | |

### ★「アプリで何ができるか」を今日はっきりさせる

出荷時ファーム＋アプリの基本機能は、分かっている範囲でこの7つ。

| 機能 | 確度 |
|---|---|
| AI会話（クラウド経由） | 確実 |
| 表情・モーション | 確実 |
| ダンス | **あるのは確実。自分で作れるのかは未確認** |
| アプリ経由のアバター表示 | 確実 |
| アプリ経由の監視カメラ | 確実 |
| アプリストア | あるらしい。**中身は未確認** |
| ESP-NOW / OTA / Home Assistant MCP | あるらしい |

**未確認の2つ（ダンスを自分で作れるか / アプリストアの中身）を今日確かめる。**
ここが「作れる」なら、DJ連携の一部をノーコードで済ませられる可能性がある。

### アバター表示と監視カメラは「捨てる」で決着済み（2026-09-08）

自前ビルドでこの2機能が失われる可能性があったが、**惜しくないので捨てる**と判断済み。
どちらもXiaoZhiのクラウド経由の機能で、自宅を頭脳にする方針と噛み合わない。

**今日は軽く見るだけでよい。** ここを検証するために時間を使わない。
浮いた時間は上の「会話まわり」と「音量・バッテリー」の実測に回す。

## この日で確定したこと

### 自前構成に行く理由が4つに増えた

1. **言うことを聞かない** — system prompt を触れないから。自前なら指示追従は自分で作れる
2. **一回一回で終わる** — 文脈も記憶も続かない
3. **アイドルが不気味** — 挙動を自分で決められない
4. **ダンスがライブ追従ではない** — 事前に曲を入れて再生する型。DJに合わせるものではない

→ 4 により、**DJ連携を自前でやる方針が確定**。アプリ側に寄せる道は無い。

### 一方で、負けている点が1つはっきりした

**速度。** 出荷時ファームのクラウドは十分に速い。
自宅Mac + Ollama + Funnel往復は、素直に作ると**確実にこれより遅くなる**。

「ローカルだから安心」だけでは、体験として劣化したと受け取られる。
→ `questions/local-brain-latency-vs-cloud`

対策の方向：
- モデルを小さくする（llama3.2:3b から。賢さより最初の音が出るまで）
- **相槌を先に返す**（考える前に「うん」と言わせる）。無音を消すだけで体感は大きく変わる
- 将来的には Realtime API 系で STT→LLM→TTS の多段遅延を潰す
