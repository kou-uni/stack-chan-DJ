> **役割：デザイナー**

> 先に「誰が・どこで・何を見て・どう感じるか」を書く。実装はそのあと。

---

## 1. 誰が使うのか

**もくもくタイムの参加者。** ひとりで手を動かしていて、詰まった人。

| | |
|---|---|
| **状況** | Bar。周りは喋っている。DJは鳴っていない（この時間だけ静か） |
| **手元** | 自分のPCと Claude Code。**そっちに主役がいる** |
| **気持ち** | 進めたい。でも講師は他の人と話している。**待ちたくない** |
| **ロボットへの期待** | 「たぶん、たいしたことは答えられない」**期待は低い** |

**★期待が低いのは弱点ではない。**
低い期待を少し超えるほうが、高い期待を下回るより、ずっと良い体験になる。

---

## 2. いまのままだと、どう感じるか

```
  合図を待つ  →  いつ話せばいいか分からない  →  話す  →  無言  →  変な答え
                          不安                            壊れてる?
```

**「性能が変だ」と思われる瞬間**は、いつも同じ形をしている。

- **間違った答えを、自信ありげに返す** ← いちばん壊れて見える
- **無言で終わる** ← 二番目
- 聞き取れないこと自体は、実はそこまで悪くない

## 3. ジャーニー（こう変える）

```
① 詰まる          ひとりで手を動かしていて、行き詰まる
② 手を伸ばす      ★頭を撫でる                    ← 起動は人が決める
③ 気づく          ★首をかしげて、LEDが緑になる    ← 「聞いてるよ」
④ 話す            ふつうに喋る（合図を待たない）
⑤ 分かる          ★「ファームの話だね?」と復唱     ← ここで誤認識が見える
⑥ 受け取る        ★短く答える／エージェントに振る
⑦ 戻る            自分のPCへ帰る
```

### 起動の手段（第一候補が使えないときのために）

| 優先 | 手段 | 条件 | 状態 |
|---|---|---|---|
| **1** | **頭を撫でる** | タッチセンサ（Si12T）が動くこと | **★2026-09-12、I2Cに現れず未使用** |
| **2** | **画面をタップ** | 実機の画面タッチが使えること | 未検証 |
| **3** | **DJ機材のパッド** | 進行役が押す | 動く。ただし参加者が押せない |
| **4** | **スマホから**（Phase 2 の操作パネル） | 土台は完成済み | **参加者が自分で押せる** |

**★1が使えないなら4。** どちらも「人が起動を決める」ことは変わらないので、
**ジャーニーは壊れない**（合図を待つ必要がない）。

4の場合、ジャーニーはこうなる。

```
② 手を伸ばす   スマホの「話しかける」を押す
③ 気づく       ★首をかしげて、LEDが緑になる     ← ここは同じ
```

### なぜ「撫でる」で起動するのか

- **タイミング問題が構造的に消える。** 合図を待つ必要がない
- 騒がしくてもウェイクワードに頼らない（台本の「タップ起動を基本にする」と一致）
- **触れるという行為そのものが体験になる**（「最重要：触らせること」）
- **手のひらサイズのロボットを撫でるのは、自然な動作**

### なぜ復唱するのか

**誤認識を隠さない。** 隠すから壊れて見える。

```
✕  （聞き間違えたまま）「農業は生産の場です」      → 壊れてる
○  「ファームの話だね?」→ 違えば人が言い直せる     → 会話になっている
```

**復唱は人間がやること。** キャラクターとして自然で、しかも誤りが即座に分かる。

## 4. キャラクター

**「全部わかる先生」にしない。** 小さいロボットに合わない。

| | |
|---|---|
| **立ち位置** | **受付と振り分け。** 全体を見て、誰に何を渡すか決める |
| **口調** | 短い。ため口。落ち着いている（声＝VOICEVOX 冥鳴ひまり） |
| **得意** | 「それ、どこに書いてある」を知っている |
| **不得意** | 長い説明。**やらないと最初に言ってある** |

### 決め台詞

| 場面 | 返し |
|---|---|
| 聞き取れない | **「ん? もういっかい」**（首をかしげる） |
| 知らない | **「それは僕より、君のエージェントが詳しいよ」** |
| 長くなる | **「長くなるから、続きは君のエージェントに聞いて」** |
| 分かった | 「◯◯の話だね」→ 短く答える |

**★どれも故障ではなく性格に見える。** ここが設計の肝。

---

## 5. 期待値を先に下げる

**掴み（Aブロック）で、進行役がこう言う。**

> 「この子は短い返事しかできません。詳しい話は、みんなのエージェントに振ります」

**そう言ってあれば、短い返事は仕様になる。**
言っていないと、同じ返事が「性能が低い」になる。

---

## 6. 技術の方針（UXから逆算）

**精度を上げるのではなく、精度に依存しない形にする。**

| 決めごと | 理由 |
|---|---|
| **全文ではなくキーワードで動く** | 振り分けに必要なのは「ファーム」「バックアップ」等。一字一句は要らない |
| **確信が低ければ聞き返す** | 間違った答えを返すより、聞き返すほうが良い |
| **合図は実機から出す**（首・LED） | **端末は当日誰も見ない** |
| 返事は40字まで | 音声は読み飛ばせない |
| 前置きを落とす | 「了解しました」は音声だと時間の無駄 |

## 6.5 撫でられたときの振る舞い

**★当日使う。** 撫でて反応を楽しんでもらうこと自体が、掴み（Aブロック）の中身。
「最重要：触らせること」（00-concept §11）はこれ。

**会話の起動にだけ使わない。** 会話の入力はスマホ。
★この2つは別の話。**「会話に使わない」＝「使わない」ではない。**

### 何が「人間らしい」か

**同じ反応を繰り返した瞬間に、機械に戻る。** 実測で分かっている（振り付けと同じ）。
人は同じことをされても、そのときで違う返しをする。

| | |
|---|---|
| **反応を複数持つ** | 照れる・くすぐったい・喜ぶ・驚く |
| **たまに嫌がる** | ★これが一番効く。**いつも喜ぶのは機械** |
| **回数で変わる** | 1回目は驚く／続けると慣れる／しつこいと嫌がる |
| **場所で変わる** | 3ゾーンある。左右で違う反応 |
| **長さで変わる** | ポンと触る＝驚く／長く撫でる＝とろける |

### 反応の設計

| 反応 | いつ | 顔 | 動き |
|---|---|---|---|
| **驚く** | 久しぶりに触られた（初回） | surprised | ビクッと上を向く → 戻る |
| **照れる** | ふつうに撫でられた | embarrassed | 首をかしげて小さく揺れる |
| **くすぐったい** | 短く何度も | happy | 小刻みに首を振る |
| **とろける** | 3秒以上撫でられた | happy | ゆっくり傾いて、戻らない |
| **嫌がる** | **しつこい**（短時間に4回以上） | sad | 顔を背ける（反対を向く） |
| **慣れる** | 何度も撫でられたあと | idle寄り | 反応が小さくなる |

**★「嫌がる」を入れる理由。**
いつも喜ぶ相手は、機械に見える。**拒否できる相手には人格を感じる。**
ただし**嫌がったまま終わらない**。少し置くと機嫌が戻る。

### やらないこと

- **同じ反応を続けて2回出す**（乱数ではなく、直前と違うものを選ぶ）
- **嫌がったまま固定する**（数十秒で戻る）
- **会話を起動する**（起動はスマホ）

## 7. やらないこと

- **常時聞いている**（プライバシーの主張と矛盾する。撫でられたときだけ聞く）
- ウェイクワード（騒音で通らない）
- 長い説明（そのためのエージェントが全員の手元にある）
- **端末を見せる**（当日の体験に数えない）
