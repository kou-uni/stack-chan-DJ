# app — 頭脳層（ここが「開発するアプリ」）

スタックチャンは I/O ゲートウェイ。**アプリはここにある。**

## v0：ペルソナボード（イベント直結・これを最優先で作る）

ハンズオンの中身がこれ。実機は1台でも人数を捌ける形にする。

```
参加者のスマホ ──QR──▶ ペルソナボード(Web)
                          │ 人格カードを投稿
                          ▼
                     Mac Studio の app
                          │ system prompt を差し替え
                          ▼
                  xiaozhi-esp32-server ──▶ スタックチャン
```

### 参加者がやること

1. QRを読む
2. 人格カードを書く（名前・口調・好きなもの・禁止事項の4項目だけ）
3. 一覧に並ぶ。進行役が1枚選んで **適用**
4. 全員でその人格のスタックチャンに話しかける
5. 「同じハードなのに別人になる」を体で見る

### なぜこの形か

- 実機が1台でも、全員が「自分の入力が反映された瞬間」を持てる
- 参加者に環境構築をさせない（Wi-Fi・書き込み・SDK が要らない）
- プロンプトが人格になる、という一番伝えたい部分だけを切り出せる
- Funnel 公開済みの構成がそのまま生きる（ボードも同じトンネルに載る）

## v1 以降（イベント後）

関門2つを越えてから触る。今回のスコープには入れない。

- **記憶**：「昨日の話だけど」が成立する。デモの核はここ
- **決定論ルーティング**：定時通知・センサー反応は if 文で書く。曖昧な自然文だけ LLM に投げる
- **カレンダー連携**：朝の予定読み上げ、直前リマインド
- **筋トレの声かけ**：自己申告トリガーが一番確実で一番早い

## 設計原則（`docs/00-concept.md` から）

- **実機は薄く保つ。** ESP32 側にロジックを入れるほど、デバッグのたびに書き込み直しになる
- **確実性が要るものは自分で書く。** 全部 LLM に任せると朝の予定読み上げが気まぐれで失敗する
- **感情タグで表情を同期する。** 返答の先頭に `(Happy)` を付けさせる。ロールを増やすと失敗するので指示は最小限
